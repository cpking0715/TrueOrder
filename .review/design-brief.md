# 前端设计走查 Brief（frontend-design review）

## 背景

TrueOrder 前端（Vue3+TS，frontend/）在 2026-10-10 做过一次完整视觉改版（提交 a1981eb，设计系统见 frontend/src/assets/main.css 头注释：「舱单检索台」——冷灰蓝纸面、海关青主色、三色信号（放行绿=精准/待查琥珀=潜在/驳回红=排除）、税号/提单号/日期/票数等数据用等宽字体）。此后 WP1/WP3/WP4 新增了一批组件，沿用了 token 但未经整体走查。

## 任务

对 frontend/src 做一次**视觉与交互一致性走查**（只读，不改任何文件），找出改版后的真实缺陷与改进点。当前界面截图在 `.review/frontend-audit/*.png`（01 首页 / 02 详情潜在 / 03 抽屉全貌 / 04 批量补全估计态 / 05 任务页 / 06-07 移动端），能看图则对照图，不能看图则纯代码走查。

## 走查清单（按优先级）

1. **新组件是否偏离设计系统**：ContactsPanel/ContactForm/ContactItem/WebsiteField/CompanySummary/ScoreSection/ContactsPanel 相关样式、JobsView、EnrichBar——对照 main.css 的 token（间距、字号、徽章、按钮、表格、色轨、mono 数据面）找不一致（写死的颜色/字号、未用 .muted/.small/.badge、行内 style）。
2. **交互状态完整性**：每个可操作元素的四态（默认/hover/disabled/loading）与错误呈现；EnrichBar 两段式状态切换是否清晰；抽屉里多组操作（查找/抓取/确认官网/新增联系人）的主次与拥挤度。
3. **信息层级**：抽屉从上到下（公司摘要→官网→联系人→得分理由→提单表）是否顺；得分理由与提单证据（本产品核心差异点）是否被新组件挤压到不可见/折叠过深。
4. **响应式**：390px 下表格/检索单/抽屉的表现（main.css 的 720px 断点覆盖是否够）。
5. **可访问性**：focus-visible 是否全覆盖新组件；按钮语义（如「关闭」是否真 button）；表格行点击的键盘可达性；颜色对比（琥珀 #8a5a00 on #faf0d7 之类）。
6. **文案**：中文界面动词是否一致（查找/补全/抓取/导出的用词）、按钮文案是否说清后果。

```
### D# [P1 明显缺陷 | P2 打磨项 | P3 建议] 标题
- 位置：frontend/src/...（文件:行，或截图编号+区域）
- 问题：…
- 建议：具体到 CSS/模板的改法
```

结尾按 P1/P2/P3 汇总数量。不要写入任何文件，不要输出过程叙述。
