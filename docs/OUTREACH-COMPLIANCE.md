# 合规备忘：联系人数据与（第二期）开发信

> **非法律意见**。本文是工程护栏的落地说明，不构成对 GDPR / CAN-SPAM 等任何法域的
> 法律判断。正式群发前请自行核实适用要求。

## 第一期：联系人数据的来源与保存

第一期只做信息获取（联系人补全与抓取），不发信。合规重点是**来源可追溯**与**可删除**：

### 来源可追溯

- 每条联系人必须带 `source`（`manual` / `csv` / `finder` / `website`）与 `source_ref`
  （接口名或页面 URL）与 `acquired_at`（获取时间）。
- 企业官网字段同样带 `website_source` 与置信度（`high|medium|low`），中低置信只作候选，
  人工确认后才用于查联系人（防止把别家公司的人当成客户）。
- 按次查询补全（Hunter 等）只对用户选定的企业调用，每次调用记入 `enrichment_calls`
  （provider、企业、额度消耗、时间），可审计、有每日上限。

### 数据最小化与保存

- 只保存业务必需字段：姓名、职位、邮箱、电话、来源、验证状态。
- 通用邮箱（`info@` 等）必须打 `is_generic` 标签，不与具名联系人混用。
- 数据来源是授权提单（企业级公开贸易记录）与官网公开页；不购买、不使用来路不明的邮箱列表。

### 可删除与不再联系

- 联系人可标记 `do_not_contact`，导出默认排除。
- 一键清除某联系人的全部数据：硬删除联系人行（第二期加活动表后，同步脱敏历史正文）。
- 数据清除后不可恢复（本地单用户模式，无备份策略时由用户自行负责备份）。

## 第二期：发信相关（随发信功能一起落地）

以下内容在第二期实现时补齐，此处仅占位：

- 发件域名 DNS 要求：SPF / DKIM / DMARC 配置说明与预热建议。
- 退订处理：`List-Unsubscribe: <mailto:...>` 头 + 正文「回复 STOP」；IMAP 轮询识别。
- 抑制名单：退订、退信、投诉、手动四种来源，发送前强制检查。
- 各地区要求：欧盟/英国（GDPR 合法利益、可退订、来源说明）与美国（CAN-SPAM：真实
  发件人、物理地址、可退订）的差异提示文案。
- 每日上限与发送间隔的运营预期（新域名冷启动送达率）。
